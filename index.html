GPS clock error investigation

How does GPS find your position when your phone's clock is wrong?

An interactive investigation. All results are calculated live from your inputs.

A phone finds its distance to each GPS satellite by timing the satellite's signal and multiplying by the speed of light. Each distance gives a circle, and the phone is where the circles cross. Light travels about 300 m in one microsecond (μs), but a phone only has a cheap quartz clock, not an atomic clock like the satellites.

Experiment 1: what does a clock error do?

Hypothesis: if the phone's clock is wrong by even a few microseconds, the calculated position will be wrong by kilometres, because every microsecond adds about 300 m to each measured distance.

Experiment 2: correcting the error by hand

All the timings are made with the same clock, so the clock error is the same for every satellite. This means every circle is too big by the same distance. If we shrink all the circles by the same amount, there should be one amount where they cross at a single point again, and that amount tells us the clock error.

Method: drag any circle inwards (all three change together) until they meet. You can also use the slider under the map.

Experiment 3: how a computer does it

A phone cannot drag circles, so it uses an algorithm instead. We used a method called Gauss-Newton least squares, which is similar to what real GPS receivers use. It repeats these steps:

  1. Start with a guess for the position and the clock error (the hollow circle).
  2. For each satellite, compare the measured distance with the distance the guess predicts. The difference is drawn as a thin arrow: outwards if the measured distance is longer, inwards if it is shorter.
  3. Combine the arrows into one move (the thick dashed arrow) and move the guess.
  4. Repeat until the guess stops moving.

There are three unknowns (x, y and the clock error), so at least three satellites are needed on a flat map. In 3D there are four unknowns, which is why real GPS needs at least four satellites.

Further testing

Here every variable can be changed, and you can drag the satellites and the true position. Some things we noticed when testing:

  • Adding measurement noise makes the position error bigger.
  • Moving the satellites close together makes the same amount of noise cause a much bigger error.
  • Unticking "Solve for the clock error" gives a large error even with no noise.

Conclusion

A clock error of only a few microseconds moved the calculated position by several kilometres, which supports our hypothesis. GPS still works with a cheap clock because the clock error is the same for every satellite. It can be treated as one more unknown and solved together with the position, as long as there is one extra satellite. This is why GPS needs four satellites in 3D and not three.

Evaluation

Our model has some limitations:

  • It is 2D, so it only needs three satellites. A 3D version with four satellites would be more realistic.
  • The map is 100 km wide, but real satellites are about 20,000 km away. The maths is the same, but real circles would look almost like straight lines.
  • We ignored delays from the atmosphere, errors in the satellites' own clocks and orbits, and relativity. Real receivers have to correct for all of these.
  • In Experiment 2 the circles snap to the answer when you get within 3 μs, because the exact answer is only a few pixels wide. This makes it easier, but less precise.

To improve it, we could add a 3D view, the delay from the atmosphere, and the relativity correction (satellite clocks run about 38 μs per day fast compared with clocks on the ground).
